# 音频算法设计文档（在本项目中的实现方案）

> 本文档说明如何把《音频算法技术文档.md》中的算法，以 **MIT/BSD 开源参考库 + 自主实现** 的方式
> 落地到本项目（Web 音频效果引擎，TypeScript + Web Audio API + AudioWorklet）。
> 前提约束：不读取/不修改任何反编译产物（`apktool-out/`、`business-code/`、`decompiled/` 及既有分析文档），
> 所有实现依据公开算法资料与参考库源码，全部新代码。
> 功能清单依据本项目公开 git 历史中的特性提交整理（20段EQ/卷积混响/de-esser/虚拟低频/
> 等响度（含按音量自适应补偿）/IEQ/限幅器/听力分析/分享串/组合场景/gapless 等）。
> **每项功能的"套用 MIT 库 / 自己写"决策见 §3 映射表的"采用方式"列与《MIT套用与自研决策表.md》。**

---

## 1. 设计目标与原则

| 原则 | 说明 |
|---|---|
| 独立实现 | 不依赖反编译代码；算法来自公开论文/标准/参考库 |
| 实时可用 | 引擎在 AudioWorklet 渲染线程内完成全部处理（128 帧/回调，~2.7 ms @48 kHz） |
| 双路径一致 | 实时链（AudioWorklet）与离线链（OfflineAudioContext/纯 JS）共用同一算法模块，导出与预览听感一致 |
| 可测 | 算法模块为无副作用纯函数/可注入采样率的类，支持单元测试与频响断言 |
| 许可干净 | 套用/移植的 MIT/BSD 代码保留版权声明；GPL 类仅阅读不引入 |
| 渐进实施 | 按"基础 EQ → 动态处理 → 空间 → 智能功能"的顺序推进，每步带回归断言 |

**采用方式定义**（详见《MIT套用与自研决策表.md》）：
- 🟢 直接套用：MIT 库作依赖引入，不改代码，保留 LICENSE；
- 🔵 许可移植：按 MIT/BSD 条款移植为 TS（或复制小文件），文件头保留版权声明；
- 🟡 借鉴自研：参考思路与架构，代码完全自己写；
- 🔴 必须自研：无合适 MIT 库，完全自写。

## 2. 总体架构

```
┌──────────────────────── 主线程（UI / 控制） ────────────────────────┐
│  UI 组件（调音台、曲线编辑器、场景面板、听力分析页）                      │
│        │ 用户参数 (f/Q/gain/开关/场景ID...)                            │
│        ▼                                                              │
│  引擎控制器 EngineController（单例）                                    │
│   ├─ 参数校验/归一化 → 场景预设解析 → 分享串解码(shareCodec)           │
│   ├─ 系数计算器 CoeffCalculator（离线求 biquad/IIR/卷积IR/补偿曲线）    │
│   ├─ 音量补偿 LoudnessComp（按音量通用曲线 → 低频/高频 shelf 提升）      │
│   ├─ 响度估计 LoudnessMeter（BS.1770 分块统计，驱动智能响度/IEQ）       │
│   └─ 分析服务（频谱特征 meyda 式、听力分析、可视化数据）                │
└──────────────┬─────────────────────────────────────┬──────────────────┘
               │ 系数/参数（消息通道）                  │ 音频数据（分析用副本）
               ▼                                      ▼
┌──────── AudioWorklet 渲染线程（实时） ──────────┐  ┌──── 离线路径 ────┐
│ AudioEffectsWorklet.process(128帧/回调)          │  │ OfflineAudioContext│
│  ├─ 输入缓冲 → M/S 解码 → Pre-EQ → 动态处理      │  │ 或纯 JS 引擎      │
│  │   → 空间(卷积/算法混响) → 低频增强 → Post-EQ  │  │ （同一算法类）    │
│  │   → 等响度/响度 → 限幅器 → M/S 编码 → 输出    │  └──────────────────┘
│  └─ 所有系数在主线程算好，这里只做乘加与插值      │
└──────────────────────────────────────────────────┘
```

**关键决策**
1. 算法类（EQBand、Deesser、Convolver、Limiter、BassEnhancer...）写成**纯 TS、无 WebAudio 依赖**，
   同时被 worklet 与离线引擎 import —— 这是"实时/离线一致"的根本保证（与既有断言体系一致）。
2. 重计算（系数、卷积 IR 分块 FFT、补偿曲线）全部在主线程完成，结果以
   `Float32Array` 消息传给 worklet；worklet 内只做系数插值（每帧线性滑变，防爆音）。
3. 分析用 `AnalyserNode` + meyda 式特征函数，与渲染链解耦。

## 4. 核心模块设计

### 4.1 `dsp/EqChain.ts` —— 均衡链（含 Q 补偿）
- 接口：`update(bands: {f:number, q:number, gainDb:number}[], fs:number)`；
  `process(samples: Float32Array, ch: number)`。
- 系数：每个 band 用 RBJ peaking 公式（TDF2 实现，移植 DSPFilters State.h 思路）；
  shelf 用架式公式（AutoEq peq.py 可对照）。
- **Q 补偿算法**（🔴 自研，保证级联总响应与目标一致）：
  1. 用各 band 系数在控制频点求级联幅频响应（FFT 采样或解析 H(z)）；
  2. 误差 e_i = 目标_i − 实测_i；gain_i ← gain_i + 0.8·e_i，迭代 2~3 次（误差 < 0.1 dB 停止）；
  3. 或对相邻 band 的 Q 做带宽重叠修正（shelf→peaking 交叠区）。
- 断言：白噪声经 20 段级联后，在各控制频点实测增益与设定值误差 ≤ 0.1 dB；
  全 0 dB 设置时级联响应 = 平直（±0.05 dB）。

### 4.2 `dsp/Convolver.ts` —— 分区卷积混响
- 输入：IR（Float32Array，可来自内置库或用户导入）；输出：wet/dry 混合。
- 实现（🔵 FFT 移植 kissfft + 🔴 分区调度自研）：
  - 分区数 P = ceil(M/L)，块长 L = 512（~10.7 ms @48k，延迟预算内）；
  - 每输入块：与各分区 FFT 卷积（预计算分区频谱），按延迟累加 → overlap-add；
  - 块频谱预计算在主线程完成；worklet 内用复数 FFT（kissfft 移植的 WASM 或自写基 2 蝶形）。
- **IR 去周期化**（🔴）：对 IR 尾部从能量包络 -60 dB 点开始乘指数衰减窗（时间常数 ~50 ms），
  保证循环卷积无周期伪影；对"房间 IR"额外做 4 kHz 以上轻微低通（模拟空气吸收）。
- 复杂度预算：P=188（2 s IR）、L=512 → 每块 188×512·log₂(512)≈ 0.9M MAC，WASM 下远低于实时预算。

### 4.3 `dsp/Deesser.ts` —— 动态齿音抑制（🔴 自研，分带式）
- 参数：center（默认 6 kHz）、Q、阈值、比率、attack/release。
- 信号流：输入 → 并联两支：干路（全通）与侧链（带通 4–8 kHz）→ 包络（√ 均值平滑，
  attack 1 ms / release 80 ms）→ 阈值压缩曲线 → 分带增益（只压高频带）。
- 关键：包络在 dB 域平滑（听感自然）；增益用"目标增益/实际"的线性插值防爆音。

### 4.4 `dsp/Limiter.ts` —— 前瞻限幅器（🔵 移植 DaisySP/signalsmith-basics 基础 + 扩展）
- 信号路径：输入延迟 L=256 帧（~5.3 ms）→ 输出 = 延迟信号 × 平滑增益 g。
- 检测：延迟线上取 256 帧窗口峰值（真峰值：对窗口做 4× 过采样插值后再取峰，🔴 自研扩展）。
- 增益：g = min(1, Thr/peak)；对 g 做 attack 0.5 ms / release 150 ms 一阶平滑。
- 目标：任意输入峰值不超过 Thr（默认 -1 dBFS）；无 audible pumping。

### 4.5 `dsp/BassEnhancer.ts` —— 虚拟低频（🔴 自研）
- 信号流：LPF(80–120 Hz) → 非线性（可选 x³ / tanh / ATSR）→ HPF(≥150 Hz) → mix。
- 参数：截止、宽度（Q）、谐波类型、mix、level；harmonics 2–4 次为主。
- 注意：非线性只在低频带内做（先 LP），否则全频互调；输出做 0.5 dB 安全裕量防削波。

### 4.6 `smart/LoudnessComp.ts` + `smart/Ieq.ts` —— 智能补偿（🔴 自研，数据公开）
- 等响度：ISO 226 表（1/3 倍频程，phon 20–90）预存；音量 α → 目标 phon 曲线插值 →
  补偿增益谱 → 拟合 4–6 段 shelf/peaking（复用 EqChain 的拟合器）。
- IEQ：分析链每 500 ms 输出长时 1/3 倍频程频谱 → 与目标曲线差 → 分段平滑 → 拟合 EQ 增益。
  所有智能增益都走"慢速平滑"（时间常数 3 s），避免跟随音乐抽吸。

### 4.7 设备档案（已移除）→ LoudnessComp 按音量自适应补偿（🔴 自研）

> **2026-08 需求变更**：不引入真实设备档案（不再使用 AutoEq 测量数据/拟合）。
> "机型频响补偿"改为**按音量大小实施补偿的通用曲线**：音量越低 → 低频 0-12dB / 高频 0-6dB 提升
> （低频 120Hz LowShelf、高频 12kHz HighShelf，Q=0.707；v2 兼容公式 low=clamp((80−spl)×0.35,0,12)、
> high=clamp((80−spl)×0.15,0,6)，spl=50+30×vol/100）。由 `dsp/LoudnessComp.ts` 的 `auto` 模式承担；
> 原 `device/DeviceProfile.ts` 与 `deviceProfile` 参数已删除。

### 4.8 `analysis/` —— 测量与可视化
- `LufsMeter`（🔴 自研）：K 加权（48 kHz 固定系数）+ 400 ms 窗/100 ms 步进 + 绝对/相对门限 → 整合 LUFS、LRA、真峰值。
- `Spectrum`（🟢 meyda + AnalyserNode）：频谱特征（质心/滚降/平坦度/MFCC）→ 可视化。
- `HearingTest`（🟡）：各频段（125 Hz–8 kHz）扫频音量阈值估计 → 个人听力曲线 → 补偿建议。
- `Pitch`（🔴 YIN 实时 + 🟢 CREPE-ONNX 离线）：双实现。

### 4.9 `offline/Separator.ts` —— 声源分离（🟢 spleeter/demucs 模型 + 🔴 任务队列自研）
- 离线任务队列：上传/选择音频 → Web Worker + ONNX Runtime Web 跑 spleeter/demucs 转换模型
  → 返回 stems（Float32Array）→ 预览/导出。
- 不占实时线程；失败重试与取消机制；模型权重按用户同意后按需下载（MIT 许可）。

### 4.10 `codec/ShareCodec.ts` —— 分享串（🔴 自研）
- 格式：版本号 + 场景/各模块参数 + 校验和 → base64url；解析时白名单校验、
  数值范围钳制（防注入，对应既有"分享串防注入"修复）。

## 5. 数据流与参数生命周期

```
用户操作(UI) → 场景/参数对象(不可变) → EngineController
   ├─ 校验/归一化 → CoeffCalculator（主线程, 非实时）
   │      ├─ EqChain: bands → biquad 系数数组 + Q补偿迭代
   │      ├─ Convolver: IR → 分区频谱表 + 去周期化
   │      ├─ Deesser/Limiter/Bass: 阈值/时间常数 → 平滑系数
   │      ├─ LoudnessComp/Ieq: 曲线 → 拟合 bands → (复用 EqChain)
   │      └─ LoudnessComp: 音量 → 低/高频补偿增益（shelf 系数）
   │      ▼
   │   {`Float32Array`/结构化消息} ——postMessage→ AudioWorklet
   ▼
AudioEffectsWorklet.process: 读消息→若版本变化则原子替换参数块→
  逐帧系数插值 → 模块流水线执行 → 输出
```

- 参数块带 `seq` 序号与 `applyTime`，worklet 内按 AudioContext 时间戳切换（避免中间态）。
- 分析链独立采样（可 decimate 到 10 Hz 更新率），与渲染链零耦合。

## 6. 实时性能预算（@48 kHz，128 帧回调，x86/WASM）

| 模块 | 每帧 MAC 估算 | 说明 |
|---|---|---|
| 20 段 biquad × 2ch | ~20×5×2×128 ≈ 25.6k | TDF2 每样本 5 MAC |
| 卷积混响（2 s IR, L=512, WASM FFT） | ~0.9M（分块摊还） | 主要开销，WASM 单线程可承受 |
| Deesser + Limiter + Bass | ~10k | 包络/增益 |
| 等响度/智能（主线程） | 0（低频更新） | 3 s 时间常数 |
| 合计 | ~1M MAC/帧 ≈ 480 MMAC/s | 现代 CPU WASM 实时无压力；低端设备可切算法混响 + 短 IR |

**降级策略**：设备能力检测 → 高档（卷积+全链）/中档（算法混响+EQ）/低档（EQ+限幅器）。

## 7. 测试与验证策略

1. **系数级单测**（vitest）：RBJ 公式对拍 DSPFilters 输出（同一 (f,Q,gain) 的系数误差 < 1e-9）；
   Q 补偿迭代收敛断言；分享串往返一致。
2. **频响断言**：白噪声 → 各模块 → FFT 实测幅频响应 vs 理论目标（≤0.1 dB 容差），
   覆盖全部 20 个控制点 + 边界频点（20 Hz / 20 kHz）。
3. **时域断言**：限幅器峰值 ≤ 阈值；de-esser 只在齿音频段触发（合成"s"信号）；
   卷积混响 IR 尾部平滑无周期伪影（自相关无尖峰）。
4. **实时/离线一致性**：同一参数、同一输入，AudioWorklet 输出与离线引擎输出逐样本误差 < 1e-6。
5. **响度断言**：合成 -23 LUFS 信号，LufsMeter 测量误差 ≤ 0.1 LU。
6. **回归套件**：沿用现有断言体系（30+ 项），每功能合入带 3–5 项新断言。
