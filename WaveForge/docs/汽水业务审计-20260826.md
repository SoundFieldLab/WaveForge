## 三、正在追的 track_v2「无效 JSON」问题

- 抛错点 requestJson（qishui-api.mjs:156）；POST 变体 :2338 / GET 兜底 :2357；仅一次 POST→GET 重试，无负缓存/退避。
- 失败最终表现为**静默换网易云/QQ 同名接播**（App.loadAndPlaySong :3746-3762），用户无感知——排查「播的不是原唱」的大坑。
- 两大嫌疑：① device_id/fp/iid 每次 `Date.now()` 现造（sodaPcAppParams :1203，上游可能回 HTML 质询页=无效 JSON 的典型 bodyHead；对比登录侧已持久化 deviceId）；② sessionOnly cookie 形态不统一（:1234）。
- 诊断工具已备好：`_debug/trackv2` 端点（PORT=3999 才暴露）+ 根目录 probe-tv2*.cjs / probe-token-vpn.cjs / tv-debug-state.json。
- 建议 P0：稳定设备指纹 + /song/url 失败给前端可感知提示而非静默换源。

## 四、与原项目对照——真正丢失的东西（按危害排序）

1. **登出不彻底（建议修）**：原版 logout 清 auth 分区 cookies + 销毁安全窗 + 写空 cookie 文件 + 删 userData 凭据；WaveForge 的 handleSodaLogout（App.tsx:5226）只删 localStorage 四键 → `persist:mineradio-qishui-auth-v6` 分区与会话文件残留有效凭据，「换账号」语义不成立。
2. **抖音 OAuth/OpenAPI 通道整体裁剪**（有意为之）：OpenAPI 搜索/token 文件/OAuth 配置全无痕迹。「仅配 clientKey 未扫码」中间态消失。
3. **song/url 响应字段缩水**：size（下载体积）、level、requestedQuality、顶层 vipLabel/net loss；错误码前缀 QISHUI_*→SODA_*（暂无消费方受害）。
4. **音频代理硬编码 localhost 绝对地址**（decryptor.mjs:460）：原版相对路径天然跟随端口；现 dev-tv-server/android-server 或远程场景会把播放器指去错误 origin。
5. 小项：公开搜索 hasMore 判断弱化（:1611 会多发空页请求）；凭据 env 重定向/旧文件迁移未带走。

**反超原版的本地增强**：解密代理 SSRF/体积/条目 LRU 三重加固、二维码过期自动重建×4、榜单/日推/伪艺人聚合路由、歌词负缓存+翻译形态扩展、评论 replies/pinned、DOM 抓取兜底桥（main.cjs:3607）。
