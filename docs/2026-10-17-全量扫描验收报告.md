## 二、P0（发布阻断）

### P0-1 应用内更新下载载荷契约断裂，打包版更新 100% 失败

- 渲染层把签名清单**包了一层**：`src/components/UpdateManager.tsx:146-150`、`:174-176` 传的是 `{ manifest: info.manifest }`。
- 主进程只认**顶层** `manifestSignature`：`desktop/update-manager.cjs:447-455`。`payload.manifestSignature` 永远取不到：
  - 打包版直接返回“当前版本要求签名更新清单（manifestSignature 缺失）”；
  - 开发版走裸载荷分支，`payload.urls` 也不存在 → “更新载荷缺少有效的地址或校验值”。
- 第二层缺陷：即使解包，`extractSignedArtifacts()`（`:94-108`）返回 `{ version, install, hot }`，而 `update:download-background` 使用 `spec.urls / spec.sha256`（`:464-466`）→ `undefined`。热更新下载仍然失败；只有 `download-and-install` 用 `spec.install` 是对的（`:484-490`）。
- 影响：设置页“立即更新 / 下载完整安装包”、启动自动提示更新，全部无法完成下载。这是打包版唯一的在线更新通道。

**修法**：主进程统一 `const manifest = payload?.manifest || payload`；热更取 `spec.hot.urls/sha256`，安装包取 `spec.install`；渲染层可直接传 `info.manifest`；补一条覆盖 `{ manifest }` 载荷的 IPC 单测（现有 `test/update-manager-security.test.cjs` 未覆盖）。

### P0-2 发布流水线会推送未签名清单，并吞掉 git push 失败

- `.github/workflows/release.yml:62-70` 只注入 `GITEE_TOKEN/GH_TOKEN`，没有挂载 `license-private-key.pem`。
- `scripts/publish-release.mjs:339-359` 找不到私钥时只 `console.warn`，仍写出**无 `manifestSignature`** 的 `update.json`；随后 `:357-358` 无条件 `gitPush(version)` 推到双源 master。
- 客户端 `resolveDownloadSpec` 会对未签名清单拒绝下载 → 用户“看到新版本、点更新失败”；更糟的是会覆盖 master 上原本可用的清单。
- `scripts/publish-release.mjs:241-252`：`git push` 失败只 `console.warn`，仍打印“已推送”，退出码 0；日志中的 URL 可能带 token。
- 附带：`GITHUB_REPO = 'YoshinoRinn/WaveForge'`（`:33`）与当前 origin `SoundFieldLab/WaveForge` 不一致（依赖 301 重定向），改名/迁移后易失效。

**修法**：CI 注入签名私钥，`existsSync` 失败直接让发布失败；无 `win-x64`/`win-x64-hot` 产物时不要把清单推到 master；push 失败置非零退出码并脱敏 URL；统一仓库常量。

### P1-1 13 处请求把 `/api` 拼了两次，三组页面整体 404

- `src/services/playlistService.ts:392`（`${cookie ? `` : ''}` 空插值）、`:419`、`:456`、`:757`、`:812`、`:920`（网易云 likelist / 私密歌单 / QQ 歌单）。

- `src/features/traditionalPc/NeteasePcCollection.tsx:459`：最近播放的“歌单/专辑/电台节目”页签不带 cookie。
- `src/services/neteaseMusicJourney.ts:37-40`：音乐旅程页不带 cookie。

### P1-4 酷狗取流丢弃登录凭据与音质/专辑参数，VIP 歌曲永远回流

### P1-5 QQ“取消喜欢/喜欢”可能写入或删除用户自建歌单

- `local-server.mjs:738-744`（旧接口 `:780-783`）解析“我喜欢”时仍保留 `name.endsWith('喜欢的音乐')`，并按上游顺序取第一个命中。
- `resolveQQFavoritePlaylistId` 的结果直接用于 `/api/qq/song/like` 的 `PlaylistDetailWrite`（`:11436-11445`）。
- 触发：自建了“XX喜欢的音乐”且排在真正的“我喜欢”之前。影响：喜欢被加进自建歌单；取消喜欢可能把歌从自建歌单**删除**（数据破坏）。
- 这正是 2026-09-24 前端 `playlistService` 已修过的同类问题（只认 `dirId=201`），服务端遗漏了。

**修法**：只认 `dirId === '201'` 或精确名 `我喜欢/我喜欢的音乐`，删除 `endsWith`。

### P1-6 Android 本机 API 无鉴权，调试令牌可被任意本机 App 读取并利用

- `android-server.mjs` 直接 `import local-server`，没有生成/注入 `WAVEFORGE_LOCAL_TOKEN`；`local-server.mjs:151` 读取为空 → `server/local-service-auth.mjs:8-18` fail-open（`return true`）。
- `tv-extensions.mjs:35` 把 `debugAccessToken` 打印进 `serverLogs`；`:679-681` 的 `GET /api/tv/logs` 无鉴权；`:626-635` 的 `POST /api/tv/debug-mode` 无鉴权；`/api/tv/remote-status` 还会返回 25567 遥控配对 token。
- 攻击链（Android/TV）：任意本机 App → `POST 127.0.0.1:3001/api/tv/debug-mode {enabled:true}` → `GET /api/tv/logs` 读令牌 → 局域网 `:3008/update?token=` 覆写 `dist/` 前端 → 同源读取平台登录态。
- 即便不碰调试服务，本机任意 App 也能直接调用 3001 的全部读写路由。

**修法**：Android 启动时生成随机 token 注入 Node（并让 WebView 请求带上）；`/api/tv/debug-mode` 增加本机一次性口令；日志脱敏；`remote-status` 只在主 WebView 会话内返回 token。

### P1-7 桌面融合重建后导航守卫失效；`<webview>` 守卫挂错对象

- `desktop/main.cjs:9101`：融合穿透重建主窗时调用 `guardAgainstExternalNavigation(win)`，但函数签名是 `webContents`（`:595`），`will-navigate` 被挂到 `BrowserWindow` 上，静默不生效（创建路径 `:3906` 是正确的）。
- `assertMainSender`（`:2488-2492`）只校验 `sender/senderFrame`，不校验当前 URL；主窗一旦被导航到外部站点，仍被视为受信来源。
- `<webview>` 守卫注册在 guest 的 contents 上（`:440-467` 的 `contents.on('will-attach-webview')`），而该事件属于 **embedder** 的 webContents；`webviewTag: true`（`:3901`）开着 → 白名单、partition 限制、剥 preload 全部是死代码。
- 登录/桥接窗口只监听 `will-navigate`，全仓无 `will-redirect`（服务器 302 不触发前者）。
- 影响：融合模式下一次同窗导航即可让外部页面进入主窗，调用剪贴板、酷狗会话、设备授权重置、壁纸写入等敏感 IPC；`<webview>` 侧可加载非白名单站点/携带任意 preload。

**修法**：重建路径改传 `win.webContents`；`assertMainSender` 增加允许文档 URL 校验；`will-attach-webview` 挂到主窗 webContents 并强制 `sandbox`/删除 preload；统一加 `will-redirect` 守卫。

### P1-8 更新应用失败会无限重启循环

- `desktop/update-manager.cjs:410-421`：启动时只要有 pending 就 `spawnUpdater()` 并退出。
- `desktop/update-applier.cjs:113-127`：替换失败只写 `updater-error.log`，仍按 relaunch 标志重启旧版本；失败时 pending 不清理。
- 影响：杀软锁 `app.asar`、安装目录只读、磁盘满等持续失败场景下，应用秒级“启动→退出→再启动”，用户只能手动删 `%APPDATA%\...\update`。

**修法**：pending 记录失败次数/时间，启动最多自动重试一次，之后进入 `blocked` 正常起 UI；失败时删除 relaunch 标志。

### P1-9 酷狗扫码登录后 userId 被 App 删除，红心/加歌单提示“未登录”

- `src/components/KugouLoginPanel.tsx:135-141` 在回调前把 `kugou_user_id/avatar` 写入 localStorage。
- `src/App.tsx:8935-8944` 登录处理先删除这两个键并清空 state；`:8946-8959` 只在**没有昵称**时才去拉用户信息；`:8962-8968` 再读 localStorage 得到的已是空串。
- 面板回调传了 nickname（`:141`），所以自愈分支被跳过 → `kugouUserId=''`。
- 影响：本次会话内红心恒为 false，“添加到歌单/我喜欢”提示先登录；重启后可能经 `getKugouSession` 恢复。

**修法**：删除前先读取面板写入值并透传 userId/avatar，或同账号登录不清。

### P1-10 歌单详情缓存命中分支不推进请求序号，旧请求覆盖新歌单

- `src/App.tsx:4864-4871`：命中 60s 缓存直接 `setDetailPlaylist + return`，没有 `++playlistDetailRequestSeqRef`，也没有复位 loading。
- 场景：先打开未缓存的歌单 A（慢），再打开已缓存的歌单 B；A 返回时序号仍是最新 → 页面从 B 被覆盖成 A，B 的 loading 也由 A 的 finally 结束。
- 影响：显示错误歌单；共享机器上 60s 内还可能看到上一账号的缓存。

**修法**：缓存分支同样自增 seq 并复位 loading；`playlist-content-changed`/登出时清 `playlistDetailCacheRef`。

### P1-11 “下一首播放”重预载使用旧队列，插入曲会被跳过

- `src/App.tsx:5236-5251` 在 `setPlaylist` 之后 `setTimeout(() => preloadUpcomingSongs(currentIndexRef.current, nextRevision, playMode), 0)`，没有传新队列。
- `preloadUpcomingSongs`（`:5482-5483`）在无 override 时回退到闭包里的旧 `playlist`（当前渲染帧）。
- 影响：开启 gapless/AutoMix/交叉淡化时，引擎按旧顺序预载原下一首；提交时按 key 在新队列里找到 `current+2`，刚插入的“下一首”被静默跳过（音频/UI 跳到错误曲目）。

**修法**：先在本地算出 `next` 并传给 `preloadUpcomingSongs`，或让 preload 默认读 `playlistRef.current`。

### P1-12 播放状态机：暂停/seek/看门狗/albumGapless 的边界失败

均已在 `src/hooks/useAudioPlayer.ts` / `src/services/albumGapless.ts` 复核：

1. **AI 长混音源曲结束后按暂停，反而继续播放**（`:3866-3868`）：渲染过渡中源 deck 被静音但继续播，`ended` 后 `paused=true`；`togglePlay` 走 `active.paused` 分支 → `active.play()` 让已结束元素从头起播，过渡继续，下一首照常开始。用户的“暂停”被吞掉。
2. **过渡中 seek 作用到错误 deck/时间轴**（`:3936-3947`、`:4034`）：`cancelScheduledTransition` 会发 `playing`（`:1150-1152`），但 `wasPlaying` 来自源 deck 的 `paused`；源已 ended 时 seek 后不恢复播放 → UI 显示播放、时间冻结。视觉已切到目标曲后拖动，写入的仍是源 deck `currentTime`（按源曲时长截断）。
3. **看门狗不失效在途 handoff**（`:1301-1354`、`:1803-1867`、`:1178`）：`forceEndStuckTransition` 不递增 `transitionExecutionRevisionRef`、不清 `handoffPendingCountRef`；迟到的 `startTargetAfterBuffer` 仍会把目标 deck 拉到 1 并起播，提交被状态守卫丢弃 → “听到下一首、界面停在上一首”。若 `play()` 永不 settle，源曲 ended 会被永久忽略。
4. **albumGapless handoff 失败无人收尾**（`albumGapless.ts:514-542`、`gaplessIntegration.ts:57`）：失败只恢复输出增益，不调用 `onTransitionCancel`；`transitionStuckDeadlineRef` 在 albumGapless 路径从未设置（`useAudioPlayer.ts:1361` 直接 return），`handleTimeUpdate` 在 `running-transition` 下又直接 return（`:3120`）→ 静音 + 歌词/进度冻结。

**修法**：过渡中暂停/seek 先判断过渡状态并统一走取消路径；seek 按 `transitionVisualStore` 决定目标/源时间基准；看门狗递增 revision、清 pending、按实际增益选择 deck；albumGapless 所有失败分支发 cancel 并设置 deadline。

### P1-13 TV 调试 WebSocket 不带配对令牌，调试台遥控/重载命令永远无效

- `src/tv/debugRemote.ts:39`：`new WebSocket('ws://localhost:3008/ws')`。
- `tv-extensions.mjs:151-158`：`verifyClient` 要求 `?token=` 或 `X-WaveForge-Debug-Token`，否则拒绝。
- 影响：开发者模式下 SPA 连不上 3008，调试台的 control/reload 命令全部失效（HTTP 日志上报正常）。这是开发工具链问题，不影响普通用户。

**修法**：通过本机接口下发 token 后拼到 WS URL；或主 WebView 初始化时由原生注入。

## 四、P2（明确逻辑缺陷 / 账号隔离 / 安全加固 / 发布流程）

### 账号与数据一致性

1. **网易云 trackIds 缓存无账号维度** — `local-server.mjs:10118-10121` 只用 `String(id)` 做键。A 账号打开私有歌单后，5 分钟内 B 账号/游客用同一 id 走分页详情会拿到 A 的完整 trackIds（后续歌曲详情是公开接口）。修法：键加 cookie 指纹，写歌单/喜欢后失效。
2. **QQ 用户主页失败被缓存成“0 关注/0 粉丝”10 分钟** — `local-server.mjs:13206-13223` 不检查上游 `code`/HTTP 状态，`|| 0`/`|| []` 后 `setRecommendCache`。修法：逐个校验，失败返回 502 且不写缓存。

### 缓存 / 性能

13. **`largeObjectCache` 过期条目永远删不掉** — `src/services/largeObjectCache.ts:149-163`：`if (!expired) found.push(...)`，`doomed` 恒空。修法：过期项也收集（或单独 `expiredKeys`）。
